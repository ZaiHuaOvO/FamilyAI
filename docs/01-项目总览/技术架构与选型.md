# 技术架构与选型

## 1. 总体架构

```text
iPhone / iPad / 家庭内的其他电脑
              │
              │ HTTP + API Token
              ▼
     FastAPI（本项目编写）
     - 身份验证
     - 请求校验
     - 超时与限流
     - 统一 API
     - 记录必要的运行日志
              │
              │ 只访问本机
              ▼
      Ollama：127.0.0.1:11434
              │
              ▼
      本地开源大模型
              │
              ▼
     MacBook Pro M3 / 16GB
```

### 组件职责

| 组件 | 职责 | 不负责 |
|---|---|---|
| 客户端（iPhone / iPad / 电脑） | 发起 HTTP 请求，携带 Bearer Token | 直接访问 Ollama |
| FastAPI（本项目） | 认证、参数校验、超时、并发限制、限流、日志、统一错误、模型白名单 | 模型推理 |
| Ollama | 加载模型、执行推理、提供本机 HTTP API | 对外暴露、认证、业务校验 |
| 本地模型 | 生成回答 | 保存长期记忆 |

关键边界：**Ollama 只监听 `127.0.0.1:11434`，FastAPI 是局域网唯一入口。**

## 2. 为什么后端选择 Python + FastAPI

V1 只做转发时，NestJS 与 FastAPI 都能胜任。选择 FastAPI 的主要原因是长期方向：

- Family AI 后续计划加入文档解析、Embedding、RAG、知识库、工具调用和 AI 工作流。
- 相关开源工具在 Python 生态中更集中：Ollama Python SDK、LangChain Ollama 集成、LlamaIndex 等。
- FastAPI 用少量代码即可获得请求校验与自动 OpenAPI 文档，便于测试与协作。

| 选择 | 优点 | 判断 |
|---|---|---|
| **Python + FastAPI** | AI 工具衔接自然、自动 API 文档、起步简单 | **采用** |
| NestJS + TypeScript | 结构清晰、熟悉 | 适合纯业务 API，但会让 AI 能力分散在 TS/Python 两套服务 |
| Go | 轻量、部署简单 | V1 无性能瓶颈；AI 生态整合不如 Python 直接 |
| Rust | 性能与资源控制强 | 学习、调试与生态接入成本偏高 |

> 选择 Python 不代表需要先系统学习 Python。AI Agent 负责实现，人工重点检查架构、行为、安全、测试和验收结果。

## 3. 技术栈

### V1 直接使用

| 技术 | 用途 | 说明 |
|---|---|---|
| [Ollama](https://github.com/ollama/ollama) | 本地模型运行时与推理 API | 只监听本机 |
| [Python](https://www.python.org/) 3.12 | 后端语言 | 项目由 uv 管理为 3.12.15 |
| [FastAPI](https://github.com/fastapi/fastapi) | HTTP 路由、校验、OpenAPI | 使用 `fastapi[standard]` |
| [uv](https://github.com/astral-sh/uv) | Python 版本、依赖、虚拟环境、lock 文件 | 已安装 0.13.1 |
| [httpx](https://www.python-httpx.org/) | FastAPI 异步调用 Ollama | 不使用同步请求 |
| [pydantic-settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/) | 从环境变量 / `.env` 读取配置 | 密钥不进源码 |
| [pytest](https://docs.pytest.org/) + pytest-asyncio | 接口与参数测试 | 以 mock 为主 |
| [ruff](https://docs.astral.sh/ruff/) | 静态检查与格式检查 | 提交前必须通过 |

### 后续评估（V1 不引入）

- **Open WebUI**：测试模型用的可选聊天网页。
- **Ollama Python SDK**：可替代直接使用 httpx，但 V1 先用 httpx 减少抽象层。
- **LangChain / LlamaIndex / AnythingLLM / Dify**：RAG 或工作流阶段再评估。
- **Tailscale**：需要外网访问时优先采用私有网络，不做公网端口映射。
- **llama.cpp / MLX-LM**：推理底层替代方案；先跑通 Ollama，不并行维护多个运行时。

## 4. 请求流程（V1 目标状态）

```text
客户端请求
    ↓
FastAPI 检查 Bearer Token（常量时间比较）
    ↓
校验 message：非空、长度 ≤ MAX_MESSAGE_CHARS、JSON 格式正确
    ↓
并发限制（信号量）与超时控制
    ↓
httpx 异步请求 127.0.0.1:11434/api/chat（stream=false）
    ↓
解析 Ollama 响应；模型不存在 / 连接失败 / 超时分别映射为明确错误
    ↓
返回统一 JSON：message、model、duration_ms
    ↓
记录：时间、路由、状态码、耗时、错误摘要（不含 Token 与聊天正文）
```

## 5. 代码模块规划

```text
src/family_ai_api/
├── __init__.py
├── main.py                 # 创建应用、挂载路由、生命周期（已实现）
├── config.py               # 环境变量与配置（已实现）
├── security.py             # Bearer Token 验证（已实现）
├── routers/
│   ├── __init__.py
│   ├── health.py           # GET /api/v1/health（已实现）
│   ├── models.py           # GET /api/v1/models（已实现）
│   └── chat.py             # POST /api/v1/chat（已实现）
└── services/
    ├── __init__.py
    ├── limits.py           # 限流（已实现）
    └── ollama_client.py    # 与本机 Ollama 通讯（已实现）
```

原则：HTTP 层（routers）与模型服务层（services）分离，测试时可以 mock 服务层，不加载真实模型。

## 6. 部署拓扑

| 项目 | 开发阶段 | 局域网阶段 |
|---|---|---|
| FastAPI 监听 | `127.0.0.1:8000` | `0.0.0.0:8000`（由 `.env` 配置） |
| Ollama 监听 | `127.0.0.1:11434` | **保持不变** |
| 访问来源 | 本机 | 家庭 Wi-Fi 内设备 |
| 公网 | 关闭 | 关闭，不做端口映射 |
| TLS | 无（本机开发） | V1 无；后续可评估 Tailscale 或反向代理 |
