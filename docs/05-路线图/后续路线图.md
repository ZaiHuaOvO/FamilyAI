# 后续路线图

> V1 完成后逐项决定是否实施。每一阶段都必须保持“可独立验收、可回退”的原则。

## V1（当前）

Mac 本地模型 + 带 Token 认证的 HTTP API，家庭局域网可用。

## V1.1：调用体验（已完成，`v1.1.0`）

- SSE 流式输出（`POST /api/v1/chat/stream`）。
- 客户端携带的对话历史（可选 `history`，服务端不持久化）。
- 请求日志查询接口与查看页面（只记录元数据，不含聊天正文）。
- 验收重点：认证/校验/限流对流式接口仍有效，日志不泄露内容。

## V2：知识库与 RAG（已完成，`v2.0.0`）

- 轻量自建：Ollama Embedding + SQLite + numpy。
- 首版索引示例 Markdown/TXT 文档，返回答案与来源。
- Embedding：`qwen3-embedding:0.6b`。
- 实测：2 个文档 / 3 个片段；RAG 查询约 7.3～7.5s；来源命中正确。

## V3：长期记忆（已完成，`v3.0.0`）

- 显式记忆 + 自动提取混合；聊天默认不使用，需 `use_memory: true`。
- 全家共享记忆，可查看、编辑、删除；提供管理页面。
- 自动提取只读用户消息，排除敏感信息，后台执行。
- 验收重点：日志不含记忆/聊天内容，删除与来源可追溯。

## V4：家庭任务与提醒

- 日历、天气、提醒规则。
- 主动通知必须可关闭。
- 验收重点：避免打扰与误触发。

## V5：工具调用

- 博客 API、GitHub、日程等。
- 修改数据、发送消息、操作家居需要明确权限与人工确认。
- 验收重点：最小权限、确认流程、审计日志。

## V6：家庭成员权限

- 夫妻独立账户、各自私人记忆、共享家庭记忆。
- 访问审计。
- 验收重点：权限隔离，避免信息越界。

## V7：Apple 客户端

- iPhone / iPad / macOS 客户端、Widget、推送。
- 验收重点：Token 安全存储、网络切换、离线错误处理。

## V8：外部访问

- 优先 Tailscale 等私有网络。
- 设备管理与密钥轮换。
- 不直接开放无保护的公网 API。

## 通用前置条件

每一阶段开始前都必须满足：

- 上一阶段验收通过并有记录。
- 安全规范未被削弱。
- 有回退方案。
- 有明确的完成定义。
