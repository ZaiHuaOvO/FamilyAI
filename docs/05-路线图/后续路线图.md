# 后续路线图

> V1 完成后逐项决定是否实施。每一阶段都必须保持“可独立验收、可回退”的原则。

## V1：基础服务（已完成，`v1.0.0`）

Mac 本地模型 + 带 Token 认证的 HTTP API，家庭局域网可用。

> 当前阶段：V7（Apple 客户端），待决策。

## V1.1：调用体验（已完成，`v1.1.0`）

- SSE 流式输出（`POST /api/v1/chat/stream`）。
- 客户端携带的对话历史（可选 `history`，服务端不持久化）。
- 请求日志查询接口与查看页面（只记录元数据，不含聊天正文）。
- 验收重点：认证/校验/限流对流式接口仍有效，日志不泄露内容。

## V2：知识库与 RAG（已完成，`v2.0.0`）

- 轻量自建：Ollama Embedding + SQLite + numpy。
- 首版索引示例 Markdown/TXT 文档，返回答案与来源。
- Embedding：`qwen3-embedding:0.6b`。
- 实测：2 个文档 / 3 个片段；RAG 查询约 7.3～7.5s；来源命中正确。

## V3：长期记忆（已完成，`v3.0.0`）

- 显式记忆 + 自动提取混合；聊天默认不使用，需 `use_memory: true`。
- 全家共享记忆，可查看、编辑、删除；提供管理页面。
- 自动提取只读用户消息，排除敏感信息，后台执行。
- 验收重点：日志不含记忆/聊天内容，删除与来源可追溯。

## V4：家庭任务与提醒（已完成，`v4.0.0`）

- 本地任务 CRUD、完成状态、今日/逾期筛选与管理页面。
- 手动简报；可选 Open-Meteo 天气。
- 无主动推送、无日历读取、无邮件。
- 验收重点：任务数据不进日志/Git，天气失败不影响简报。

## V5：工具调用（已完成，`v5.0.0`）

- 服务端白名单 + JSON 规划；不依赖模型原生工具调用。
- 只读工具自动执行；内部写工具需 API 二次确认。
- pending action 与 Token 绑定、单次有效、短时过期。
- 内存审计；日志不含参数/结果/消息内容。
- 不接入外部服务或家居控制。

## V6：家庭成员权限（已完成，`v6.0.0`）

- 多 Token 成员、CLI 管理、Token 哈希。
- 记忆/任务默认私有，可共享；按成员过滤。
- 访问审计与请求日志仅 admin。
- 验收重点：私有数据隔离、旧数据迁移、Token 撤销/轮换。

## V7：Apple 客户端（代码完成，待 Xcode 构建/测试）

- iOS/iPadOS SwiftUI 聊天核心：Keychain Token、非流式/流式聊天、历史、错误提示。
- 代码位于 `ios/`，已生成 Xcode 工程与 Scheme。
- 待验证：Xcode 编译、Simulator、真机局域网权限、ATS。
- 后续可评估记忆/任务页面、Widget、通知。

## V8：外部访问

- 优先 Tailscale 等私有网络。
- 设备管理与密钥轮换。
- 不直接开放无保护的公网 API。

## 通用前置条件

每一阶段开始前都必须满足：

- 上一阶段验收通过并有记录。
- 安全规范未被削弱。
- 有回退方案。
- 有明确的完成定义。
