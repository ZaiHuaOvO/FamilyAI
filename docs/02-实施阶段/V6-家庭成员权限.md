# V6：家庭成员权限

> 状态：**已完成（2026-11-24）**  
> 前置：V5（`v5.0.0`）已完成  
> 决策依据：[V6 家庭成员权限方案决策](../06-决策记录/V6-家庭成员权限方案.md)

## 1. 目标与决定

让家庭成员拥有独立 Token，并让记忆与任务支持私有/共享，同时保留管理员对成员与审计的管理能力。

已确认的决定：

- 身份：**多 Token 成员**，Token 只存 SHA-256 哈希。
- 管理：**CLI** 创建 / 列出 / 轮换 / 撤销；Token 只打印一次。
- 可见性：记忆与任务默认**私有**，可显式 `shared`；知识库继续全家共享。
- 迁移：现有 `API_ACCESS_TOKEN` 自动映射为 `admin` 成员。
- 管理员：可查看请求日志与工具审计，但不能通过普通接口读取成员私有数据。

## 2. 架构

```text
Authorization: Bearer <member-token>
        ↓
SHA-256(token) → members 表（id, name, role, token_hash, revoked_at）
        ↓
MemberContext（member + token_key）
        ↓
记忆/任务按 owner 过滤；shared 项对全家可见
```

- 启动时 `MemberStore.ensure_bootstrap(API_ACCESS_TOKEN)`：如果不存在 `admin`，用现有 Token 创建管理员。
- CLI 使用同一个 `data/members.db`。
- 请求日志记录 `member_id`（认证成功后由依赖写入 request.state）。
- 工具审计记录 `member_id`。

## 3. 数据结构

### 3.1 成员

`data/members.db`：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `name` | 成员名（唯一） |
| `token_hash` | SHA-256 Token 哈希 |
| `role` | `admin` / `member` |
| `created_at` / `revoked_at` | 时间戳 |

### 3.2 记忆

新增 `visibility` 字段：

- `private`：仅 owner 可见、可改、可删。
- `shared`：全家可见；仅 owner 可改/删。
- 去重按 `(owner, content_hash)`；不同成员可以拥有相同内容的私有记忆。
- 旧表（`content_hash` 全局唯一）自动重建并保留数据。

### 3.3 任务

新增 `shared` 字段：

- 默认私有；`shared=true` 对全家可见。
- 列表/简报返回当前成员自己的任务 + 共享任务。
- 只有 owner 可以修改/完成/删除；其他成员对共享任务只读。

## 4. 成员 CLI

```bash
# 创建成员并打印一次 Token
uv run python -m family_ai_api.members.cli create --name alice --role member

# 列出成员（不显示 Token）
uv run python -m family_ai_api.members.cli list

# 轮换 Token（旧 Token 立即失效，并重新激活已撤销成员）
uv run python -m family_ai_api.members.cli rotate --name alice

# 撤销成员
uv run python -m family_ai_api.members.cli revoke --name alice
```

- `--db` 可覆盖成员数据库路径（放在子命令之前）。
- Token 只打印一次；不要写入文档、日志或 Git。
- 成员管理不通过 HTTP 提供，减少管理员接口的攻击面。

## 5. 接口变化

| 方法 | 路径 | 变化 |
|---|---|---|
| `GET` | `/api/v1/me` | 新增，返回当前成员 id/name/role |
| `POST` | `/api/v1/memory` | 可选 `shared`，默认 false |
| `PATCH` | `/api/v1/memory/{memory_id}` | 可选 `shared`；仅 owner 可改 |
| `GET` | `/api/v1/memory` | 返回自己的私有记忆 + 共享记忆 |
| `POST` | `/api/v1/tasks` | 可选 `shared`，默认 false |
| `PATCH` | `/api/v1/tasks/{task_id}` | 可选 `shared`；仅 owner 可改 |
| `GET` | `/api/v1/tasks` | 返回自己的任务 + 共享任务 |
| `GET` | `/api/v1/briefing` | 只统计自己的任务 + 共享任务 |
| `GET` | `/api/v1/logs` | **仅 admin** |
| `GET` | `/api/v1/agent/audit` | **仅 admin** |
| Agent 工具 | 任务/记忆 | 按成员过滤；写工具归属当前成员，可带 `shared` |

## 6. 安全与隐私

- Token 只以 SHA-256 哈希存储；认证时哈希后查询，撤销立即生效。
- Token 不写入日志、错误响应、文档或 Git。
- 私有数据按 `owner` 过滤；搜索、列表、简报与 Agent 工具都不能绕过。
- 共享项对其他成员只读；只有 owner 能修改/删除。
- 管理员不能通过普通接口读取成员私有数据。
- `/logs` 与 `/agent/audit` 仅 admin 可访问。
- 请求日志与工具审计只记录 `member_id` 等元数据，不记录内容。
- 成员轮换 Token 后，旧 Token 立即失效；绑定旧 Token 的 pending action 也随之不可确认。

## 8. 已知限制

- 成员管理仅 CLI，无 HTTP 管理页。
- 不支持删除成员，只支持撤销；其数据保留。
- 共享项只有“私有/共享”两档，没有逐成员 ACL。
- 管理员不能读取成员私有数据；如需合规查看，需要单独设计与审计。
- 成员 Token 轮换会使绑定旧 Token 的 Agent pending action 失效。
- 成员库为单进程 SQLite；不支持多进程共享。
- 没有用户名/密码登录与会话；仍使用 Bearer Token。
