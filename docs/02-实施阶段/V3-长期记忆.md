# V3：长期记忆

> 状态：**已完成（2026-10-18）**  
> 前置：V2（`v2.0.0`）已完成  
> 决策依据：[V3 长期记忆方案决策](../06-决策记录/V3-长期记忆方案.md)

## 1. 目标与决定

让 Family AI 在多次对话之间记住用户明确希望保留的信息，同时保持可见、可编辑、可删除。

已确认的决定：

- 写入方式：**显式记忆 + 自动提取混合**。
- 聊天默认**不读取**记忆；客户端传 `use_memory: true` 才启用。
- V3 使用**全家共享**记忆，数据结构预留 `owner` 字段。
- 提供 **API + 记忆管理页面**。

## 2. 架构

```text
显式记忆：
POST/PATCH /api/v1/memory → Embedding → SQLite → 可查看/编辑/删除

自动提取：
聊天请求 → 后台任务 → 严格提示词只读用户消息 → 最多 3 条
        → Embedding → SQLite（source=auto）

聊天使用记忆：
use_memory=true → 问题 Embedding → 记忆 Top-K → 注入 system 上下文 → 模型回答
```

## 3. 代码模块

| 文件 | 职责 |
|---|---|
| `memory/store.py` | SQLite 记忆表、CRUD、去重、余弦检索 |
| `memory/service.py` | 内容/标签校验、Embedding、上下文构建 |
| `memory/extractor.py` | 自动提取提示词、JSON 解析、后台写入 |
| `routers/memory.py` | 记忆 CRUD、管理页面 |
| `routers/chat.py` | `use_memory`、记忆注入、后台自动提取 |
| `main.py` | 初始化自动提取并发信号量、挂载路由 |

## 5. 接口

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| `POST` | `/api/v1/memory` | 新增记忆 | 是 |
| `GET` | `/api/v1/memory` | 列表/向量搜索 | 是 |
| `PATCH` | `/api/v1/memory/{id}` | 修改内容/标签 | 是 |
| `DELETE` | `/api/v1/memory/{id}` | 删除 | 是 |

聊天请求新增：

```json
{
  "message": "周末做什么？",
  "use_memory": true
}
```

## 6. 安全与隐私

- 记忆接口全部需要 Token；页面不嵌入数据，Token 只保存在页面内存。
- 记忆数据库 `data/memory.db` 被 `.gitignore` 忽略。
- 记忆内容不写入日志、错误响应或 Git。
- 自动提取只读取本轮用户消息，不保存助手回答或完整对话。
- 自动提取提示词明确排除临时信息与密码、证件、健康、财务等敏感信息。
- 单次最多 3 条，每条最多 200 字；来源标记为 `auto`。
- 自动提取后台执行，失败只记录错误类型，不记录消息内容。
- 记忆为全家共享；V6 再评估成员隔离。
- 删除为永久删除，由用户显式执行。

## 8. 已知限制

- 自动提取会为每次聊天增加一次后台模型调用，可能占用内存/算力；可通过 `AUTO_MEMORY_ENABLED=false` 关闭。
- 自动提取的判断依赖模型，可能漏记或措辞不理想；用户可编辑/删除。
- 记忆检索依赖 Embedding 模型；更换模型后需要重新生成记忆向量。
- 记忆为全家共享，暂不区分成员。
- 记忆页面使用浏览器 `prompt()` 做简单编辑，后续可改进为内联表单。
