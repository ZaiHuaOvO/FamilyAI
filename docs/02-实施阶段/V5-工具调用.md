# V5：工具调用

> 状态：**已完成（2026-10-18）**  
> 前置：V4（`v4.0.0`）已完成  
> 决策依据：[V5 工具调用方案决策](../06-决策记录/V5-工具调用方案.md)

## 1. 目标与决定

让模型在受控白名单内调用内部工具，改善任务、知识库和记忆的使用体验。

已确认的决定：

- 范围：**只读内部工具 + 内部写工具**。
- 写操作：**API 二次确认**，服务端只生成 pending action，不直接执行。
- 外部服务：**首版不接入**博客、GitHub 或其他外部 API。
- 审计：**内存审计**，只记录元数据。
- 机制：**服务端规划 + 白名单执行**，不依赖模型原生工具调用。

## 2. 工具列表

| 工具 | 类型 | 作用 |
|---|---|---|
| `get_briefing` | 只读 | 今日/逾期任务简报（可选天气） |
| `list_tasks` | 只读 | 按状态/到期筛选任务 |
| `search_knowledge` | 只读 | 检索本地知识库 |
| `list_memories` | 只读 | 检索长期记忆 |
| `create_task` | 写 | 新建任务（需确认） |
| `complete_task` | 写 | 标记任务完成（需确认） |
| `add_memory` | 写 | 新增记忆（需确认） |

## 3. 流程

```text
用户消息
  ↓
规划器（模型输出 JSON：tool + arguments）
  ↓
参数白名单校验
  ↓
只读工具：执行 → 工具结果 → 模型生成回答
写工具：创建 pending action（不执行）→ 客户端确认 → 执行 → 审计
```

### 3.1 写操作确认

1. `/agent/chat` 返回 `pending_action`（id、工具、参数、过期时间）。
2. 客户端调用 `/agent/actions/{id}/confirm` 执行一次。
3. 动作与创建它的 Token 绑定；单次有效；默认 5 分钟过期；重启后清空。
4. 也可调用 `/cancel` 取消。
5. 确认接口会再次校验参数。

### 3.2 日期防幻觉

4B 规划器会编造 `due_at`。服务端增加日期解析：

- 只有用户明确写出日期（`2026-10-20`、`10月20日`）或“今天/明天/后天”时才设置 `due_at`。
- 其他情况强制 `due_at=None`，忽略模型编造的日期。
- 已验证：“明天买菜” → 明天日期；“买牛奶” → 不设置日期。

## 7. 安全与隐私

- 白名单之外的任何工具名一律拒绝。
- 不支持 Shell、任意文件、任意网络请求或家居控制。
- 写操作必须确认；模型不能自行确认。
- 参数按白名单与类型/范围校验；多余参数拒绝。
- 工具结果传给模型前截断到 `AGENT_MAX_TOOL_RESULT_CHARS`。
- 审计只记录时间、工具名、读写类型、状态、耗时、动作 id；不记录参数或结果正文。
- 动作与 Token 绑定，单次有效，默认 5 分钟过期。
- 日志只记录请求路径等元数据，不记录 Agent 消息内容。

## 9. 已知限制

- 规划器依赖本地模型，可能选择错误工具或返回无法解析的 JSON；无效计划会退化为普通回答。
- 写操作 pending action 与审计均保存在内存，重启后清空。
- 确认后的动作立即删除；执行失败需要重新规划。
- Agent 聊天暂不支持流式输出、历史消息或记忆自动注入。
- 每个 Agent 请求通常需要两次模型调用（规划 + 回答），延迟高于普通聊天。
- 外部服务（博客、GitHub、邮件、家居）未接入。
