# 阶段1：在 Mac 上运行本地模型

> 状态：**已完成（2026-10-18）**  
> 前置：阶段0 已完成  
> 产出：本机可对话的 Ollama 模型；回答质量、延迟与内存压力记录

## 1. 目标

让 MacBook Pro M3 / 16GB 稳定运行一个较小的本地模型，并完成多轮中文对话验证。本阶段不写任何后端代码，不开放网络端口。

## 2. 安装 Ollama

建议从官方下载页面安装 macOS 版本：

<https://ollama.com/download>

也可以使用 Homebrew：

```bash
brew install --cask ollama
```

安装后打开 Terminal 验证：

```bash
ollama --version
```

如果命令找不到，先确认应用已安装、Terminal 已重开，再排查 PATH。不要继续后续步骤。

安装完成后，Ollama 通常会在登录后自动启动本机服务，默认监听：

```text
127.0.0.1:11434
```

### 2.1 本机实际安装记录（2026-10-18）

| 项目 | 实际结果 |
|---|---|
| Homebrew Cask | **失败**：Homebrew 4.4.1 无法识别 macOS 27.0.1（`MacOSVersion::Error`） |

| 安装位置 | `/Applications/Ollama.app` |

| 隔离属性 | 已移除 `com.apple.quarantine` |
| 服务 | 0.40.6，监听 `127.0.0.1:11434` |

> 使用第三方 GitHub 镜像时，必须校验官方发布的 SHA256。校验不一致时不要安装。

## 3. 选择并下载模型

M3 / 16GB 的统一内存要同时容纳系统、应用、模型权重与上下文缓存。**先用 4B 级别量化模型跑通全部链路**，不要在第一天尝试大模型。

示例（以官方模型页当前列出的标签为准）：

```bash
ollama pull qwen3.5:4b
```

模型名称与大小可能变化，执行前查看：

- <https://ollama.com/library/qwen3.5>
- 或在终端使用 `ollama list` 核对本机已有模型

下载完成后：

```bash
ollama list    # 查看本机模型
ollama ps      # 查看当前已加载模型
```

## 4. 本机对话验证

```bash
ollama run qwen3.5:4b
```

建议至少验证以下问题（也作为后续性能基线的固定问题）：

1. 请用中文解释什么是本地大模型，以及它和云端 API 的区别。
2. 请用三句话介绍 RAG 的基本流程。
3. 请帮我总结一下：家庭局域网内自建 AI 服务需要注意哪些安全问题？
4. 请写一段 100 字左右的家庭周末活动建议。
5. 请解释 16GB 统一内存运行 4B 模型时，内存压力可能来自哪里。

完成多轮对话后，使用 `/bye` 退出（不同版本命令可能不同，也可 `Ctrl+D`）。

## 5. 记录指标

| 指标 | 记录方式 | 实际值（2026-10-18） |
|---|---|---|
| 首次加载模型耗时 | 从执行到首次回答的时间 | 冷启动总耗时 4.3s，其中加载 2.2s |
| 模型已加载后的简单回答耗时 | 目测或秒表 | 1.7～3.0s（经 FastAPI 端到端） |
| 长回答延迟与生成速度 | 观察输出速度 | 30 token 约 1.6s（约 18 token/s，短回答） |
| 回答质量 | 主观 1～5 分 + 备注 | 5/5，中文准确、表达自然 |
| 内存压力 | 活动监视器 → 内存 | 模型加载后 4.1GB、100% GPU；系统空闲内存约 29%；swap 已用 3.6GB/4GB（有历史占用，需持续观察） |
| 模型占用磁盘 | `ollama list` | 4.0GB |

### 5.1 本机实测（2026-10-18）

- 模型：`qwen3.5:4b`，Ollama 0.40.6，MLX runner，上下文 4096。
- 冷启动：`ollama stop` 后重新请求，总耗时 4.3s，`load_duration` 2.2s。
- 热启动：经 FastAPI 的两次真实请求分别耗时 3.0s 和 1.7s。
- `ollama ps`：4.1GB，100% GPU。
- `sysctl vm.swapusage`：已用约 3.6GB。该值包含其他应用的历史占用；若持续偏高且系统卡顿，优先降低模型体量/上下文或关闭其他应用。

### 5.2 思考型模型说明

`qwen3.5:4b` 是思考型模型，默认会把推理过程放在响应的 `message.thinking` 中。若输出 token 上限较小，可能出现 `content` 为空、只有 thinking 的情况。

本项目的 Ollama 请求显式设置 `"think": false`，让模型直接返回答案，避免把思考过程当成回答，也更符合 V1 的响应结构。

判断标准：模型回答可用、系统无明显卡顿、内存压力不长期处于黄色/红色。若明显卡顿，先降低模型体量或上下文，而不是增加基础设施。

## 6. 安全要求

- 不修改 Ollama 默认监听地址，不开放 11434 端口。
- 不安装额外的推理引擎（llama.cpp、MLX 等），V1 只使用 Ollama。
- 不在本阶段配置路由器端口映射或公网访问。
- 不把模型文件、日志或私人对话提交到 Git。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `ollama: command not found` | 确认应用安装位置；重开 Terminal；检查 PATH |
| `model not found` | 用 `ollama list` 或官方模型页确认准确标签 |
| 下载很慢或中断 | 重试 `ollama pull`；确认网络；不要同时下载多个大模型 |
| 回答很慢 | 检查模型是否首次加载；关闭占用内存的应用；改用更小模型 |
| 系统明显卡顿 | 停止对话，降低模型体量/上下文；检查活动监视器内存压力 |
| 端口被占用/服务异常 | 重启 Ollama 应用；必要时查看其日志，不要直接关闭防火墙 |
