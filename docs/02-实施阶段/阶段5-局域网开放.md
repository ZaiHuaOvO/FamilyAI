# 阶段5：在家庭局域网开放 API

> 状态：**已完成（2026-10-18）**  
> 前置：阶段4 的认证、输入校验、超时与并发保护已通过验收  
> 产出：家庭 Wi-Fi 内其他设备可带 Token 调用 FastAPI；Ollama 仍只监听本机

## 1. 原则

- **只改变 FastAPI 的监听地址**，不改变 Ollama。
- 不开放 11434 端口，不做公网端口映射。
- 局域网不等于可信网络：认证必须始终开启。
- 先确认安全措施有效，再开放访问。

## 2. 修改监听地址

本机开发（默认）：

```dotenv
APP_HOST=127.0.0.1
```

准备从家庭 Wi-Fi 设备访问时：

```dotenv
APP_HOST=0.0.0.0
```

启动方式不变：

```bash
uv run uvicorn family_ai_api.main:app --host 0.0.0.0 --port 8000
```

长期运行时去掉 `--reload`。`--reload` 仅用于开发。

> 确认 `.env` 仍被 Git 忽略；不要提交包含局域网地址或真实配置的 `.env`。

## 3. 查询 Mac 的局域网 IP

方式一（Wi-Fi 常见接口 `en0`）：

```bash
ipconfig getifaddr en0
```

方式二：系统设置 → Wi-Fi → 详细信息 → IP 地址。

示例（请使用实际地址）：

```text
192.168.1.20
```

IP 可能变化。稳定使用后可在路由器中为 Mac 设置 DHCP 地址保留；V1 不需要端口映射。

## 4. 确认 Ollama 仍只监听本机

```bash
lsof -nP -iTCP:11434 -sTCP:LISTEN
```

预期只出现 `127.0.0.1:11434`（或 `::1`）。若出现 `0.0.0.0` / `*`，先停止并修复 Ollama 监听配置，不要继续。

## 5. 从另一台设备测试

在同一家庭 Wi-Fi 下的另一台电脑执行：

```bash
curl http://192.168.1.20:8000/api/v1/health
```

带 Token 调用聊天（替换为真实值）：

```bash
curl http://192.168.1.20:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_REAL_TOKEN' \
  -d '{"message":"请确认家庭局域网 API 可以正常调用。"}'
```

同时验证：**不带 Token 时必须失败**。如果局域网内无 Token 也能调用，立即停止服务并修复。

**Token 安全：** 测试期间真实 Token 曾出现在对话中，已立即轮换；旧 Token 返回 401，新 Token 工作正常。文档与 Git 中不保存任何真实 Token。

## 6. 排错顺序

连接失败时依次检查：

1. Mac 与测试设备是否连接同一个 Wi-Fi / 局域网。
2. FastAPI 是否绑定到 `0.0.0.0`，进程是否仍在运行。
3. IP 与端口是否正确（8000，不是 11434）。
4. macOS 防火墙是否拦截 Python / uvicorn 的入站连接。
5. Token 是否有效、Header 格式是否为 `Bearer <token>`。

> 不要为了排错直接关闭防火墙，也不要顺手打开路由器端口转发。必要时只在防火墙中允许 Python 或特定端口，并在测试后复核设置。

## 7. 网络与客户端限制

- 不开放 11434。
- 不把 8000 映射到公网。
- 不通过 URL 查询参数传递 Token。
- 原生 iOS 请求不受浏览器 CORS 约束；V1 不配置任意来源 CORS。若以后有网页前端，再精确配置受信任来源。
- 需要外出访问时，后续评估 Tailscale 等私有网络，不直接开放公网。
- 家庭 Wi-Fi 中任何设备都不应因“连接了 Wi-Fi”自动获得信任。

## 9. 回退方式

如出现异常，将 `.env` 中 `APP_HOST` 改回 `127.0.0.1` 并重启服务，即可停止局域网访问。不要通过关闭认证来“临时解决”问题。
