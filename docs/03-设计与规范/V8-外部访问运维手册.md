# V8 外部访问运维手册（Tailscale Serve）

> 适用：V8.2 及以后。所有示例使用 `<tailnet>`、`<machine>`、`<member@example.com>` 占位，不要写入真实 Token 或家庭个人信息。  
> 底线：**只允许 Serve，禁止 Funnel**；不做路由器端口映射/DMZ/UPnP。

## 0. 前置条件

- Tailscale 账号；家庭自用符合免费 Personal 的非商业限制（额度以官网为准）。
- Mac 接电源并保持开盖；合盖/电池休眠会导致服务离线。
- 已阅读 [V8 阶段文档](../02-实施阶段/V8-外部访问.md) 与 [安全规范](安全规范.md) 第 7 节。
- 不需要也不允许在路由器上做任何端口转发。

## 1. 安装与命名

1. 在 Mac 安装**独立版** Tailscale（App Store 沙盒版是否支持 `serve` 需实测）。
2. 登录同一 tailnet，确认菜单栏 Connected。
3. 验证 CLI：

```bash
tailscale version
tailscale serve --help
```

4. 在 Admin console 把 Mac 机器名改为不含个人信息的稳定名称（例如 `family-ai-mac`）。
5. Admin console → DNS：启用 **MagicDNS** 与 **HTTPS Certificates**（证书开关最常遗漏）。
6. 记录访问地址：`https://<machine>.<tailnet>.ts.net`。
7. 每位家庭成员在 iPhone/iPad 安装 Tailscale 并登录；如需过渡期继续用局域网地址，保持 iOS Tailscale 的 **Allow LAN access** 开启。

## 2. ACL / grants

先备份当前策略到密码管理器或本地非 Git 文件。新 tailnet 默认允许全部流量；ACL 是**累加**的 accept，必须整份替换掉默认 allow-all，追加规则不会自动收紧。

推荐写法：用 `hosts` 别名指向 Mac 的 Tailscale IP，**不需要给 Mac 打 tag**。进入 Admin console → **Access controls**，在 JSON 策略编辑器里替换整份内容（保存前用 Preview 校验）：

```json
{
  "hosts": {
    "family-ai-mac": "<mac-tailscale-ip>"
  },
  "grants": [
    {
      "src": ["autogroup:member"],
      "dst": ["family-ai-mac"],
      "ip": ["443"]
    }
  ]
}
```

要点：

- `<mac-tailscale-ip>` 用 `tailscale status --json` 里的 `Self.TailscaleIPs` 第一个 IPv4（当前机器是 `100.110.170.119`，以实际为准）。
- `autogroup:member` 表示 tailnet 内所有成员。若只想允许指定账号，改用：

```json
{
  "groups": {
    "group:family": ["<member1@example.com>", "<member2@example.com>"]
  },
  "hosts": {
    "family-ai-mac": "<mac-tailscale-ip>"
  },
  "grants": [
    {
      "src": ["group:family"],
      "dst": ["family-ai-mac"],
      "ip": ["443"]
    }
  ]
}
```

- 保存后，未列出的 tailnet 流量默认拒绝，包括 SSH、其他端口和其他设备；以后需要别的服务时再加 grant。
- 只放行 443；不要放行 8000。
- ACL 只约束 tailnet 流量；局域网明文路径已在 V8.2 通过绑定 `127.0.0.1` 关闭。
- `hosts` 别名使用 IP；若节点重新注册导致 Tailscale IP 变化，需要更新别名。
- 如改用 tag 方式（可选，可能需要重新认证）：在策略里加
  `"tagOwners": {"tag:family-ai-server": ["autogroup:admin"]}`，把 `dst` 改成
  `["tag:family-ai-server"]`，然后执行 `tailscale up --advertise-tags=tag:family-ai-server`。
- 在控制台为服务端 Mac 关闭 key expiry（或接受约 180 天后重新认证）；家庭客户端保留过期。
- 不使用 Tailscale Share 把节点分享给 tailnet 外的人。

## 3. 启用 Serve

```bash
tailscale serve --bg 8000
tailscale serve status --json
tailscale funnel status
```

要求：

- `serve status` 显示 HTTPS 443 → `http://127.0.0.1:8000`。
- `funnel status` 必须为 **off**。
- **绝不要**执行 `tailscale funnel`、`tailscale serve --funnel` 或任何启用 Funnel 的命令。

在另一台 tailnet 设备验证（不应需要 `-k`）：

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://<machine>.<tailnet>.ts.net/api/v1/health
```

检查监听面：

```bash
lsof -nP -iTCP:443 -sTCP:LISTEN
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

443 不应监听在 `0.0.0.0`；8000 在绑定迁移后只应显示 `127.0.0.1`。

## 4. 实测 Serve 的 Host / X-Forwarded-For（推荐）

在应用外记录代理行为，不要新增 debug 路由：

```bash
tailscale serve reset
nc -l 127.0.0.1 8001
```

另开一个终端：

```bash
tailscale serve --bg 8001
```

从另一台 tailnet 设备访问 `https://<machine>.<tailnet>.ts.net/`，记录 `nc` 打印的 `Host`、`X-Forwarded-For`、`X-Forwarded-Proto`。完成后：

```bash
tailscale serve reset
tailscale serve --bg 8000
```

在实测前：

- 不要启用 `TrustedHostMiddleware`（Host 可能被改写，误配会全量 403）。
- 不要按 IP 限流（若 Serve 不注入 XFF，所有请求会退化为同一来源）。

## 5. 绑定迁移（V8.2，已确定）

本次已确认关闭局域网明文入口，把 FastAPI 绑定到回环；先确认 tailnet HTTPS 正常再迁移。

1. 编辑 `.env`：

```bash
APP_HOST=127.0.0.1
APP_PORT=8000
FORWARDED_ALLOW_IPS=127.0.0.1,::1
```

2. 重启 FastAPI（LaunchAgent 或手动进程）。
3. 验证：

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
curl -s -o /dev/null -w '%{http_code}\n' https://<machine>.<tailnet>.ts.net/api/v1/health
```

- 8000 只监听 `127.0.0.1`。
- 局域网 `http://<lan-ip>:8000` 应连接失败。
- tailnet HTTPS 仍返回 200。

若迁移后需要临时回退到 V7 形态：

- 把 `APP_HOST` 改回 `0.0.0.0` 并重启。
- 在验收记录中写明“LAN 明文旁路恢复，Token 是唯一防线”。
- 不要声称 ACL 保护了局域网路径。

## 6. 自启动（LaunchAgent）

登录自启动由三部分组成：

- **Tailscale**：菜单栏 Tailscale → Settings/Preferences 勾选 **Start on Login**。当前机器已设置 `TailscaleStartOnLogin=1`。
- **Ollama**：Ollama 应用设置中勾选 **Launch at login**；若系统后台任务显示 disabled，可新增用户 LaunchAgent 在登录时执行 `/usr/bin/open -a /Applications/Ollama.app`（本机使用 `com.familyai.ollama`）。
- **FastAPI**：下面的 `com.familyai.api` LaunchAgent。

> FileVault 开启时，重启后会停在解锁登录界面；必须先解锁登录，LaunchAgent 和登录项才会运行。

```bash
mkdir -p /Users/zaihua/FamilyAI/logs
chmod 700 /Users/zaihua/FamilyAI/logs
```

`~/Library/LaunchAgents/com.familyai.api.plist`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.familyai.api</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/zaihua/FamilyAI/.venv/bin/python</string>
    <string>-m</string>
    <string>family_ai_api</string>
  </array>
  <key>WorkingDirectory</key>
  <string>/Users/zaihua/FamilyAI</string>
  <key>EnvironmentVariables</key>
  <dict>
    <key>FORWARDED_ALLOW_IPS</key>
    <string>127.0.0.1,::1</string>
  </dict>
  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>
  <key>Umask</key>
  <integer>63</integer>
  <key>StandardOutPath</key>
  <string>/Users/zaihua/FamilyAI/logs/familyai.out.log</string>
  <key>StandardErrorPath</key>
  <string>/Users/zaihua/FamilyAI/logs/familyai.err.log</string>
</dict>
</plist>
```

加载与检查：

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.familyai.api.plist
launchctl print gui/$(id -u)/com.familyai.api
```

注意：

- LaunchAgent 在用户登录后启动；启用 FileVault 时重启后需先解锁登录。
- 不要把 Token 写进 plist；继续使用项目 `.env`（权限 600，已被 Git 忽略）。
- 日志目录 700、文件 600；必要时用 `tmutil addexclusion /Users/zaihua/FamilyAI/logs` 排除 Time Machine。
- 日志轮转示例（需按 `man newsyslog` 核对当前系统语法）：

```text
# /etc/newsyslog.d/familyai.conf
/Users/zaihua/FamilyAI/logs/familyai.out.log 600 3 5120 * J
/Users/zaihua/FamilyAI/logs/familyai.err.log 600 3 5120 * J
```

## 7. 成员与密钥

- 生成成员 Token（只显示一次）：

```bash
cd /Users/zaihua/FamilyAI
uv run python -m family_ai_api.members.cli create --name <member> --role member
```

- 让成员在自己的设备上直接输入；不要经聊天、邮件、文档传递；不要 `export TOKEN=...` 留在 Shell 历史。
- 调试时交互式读取，避免出现在命令历史：

```bash
read -r -s TOKEN
curl -s -H "Authorization: Bearer $TOKEN" https://<machine>.<tailnet>.ts.net/api/v1/me
unset TOKEN
```

- 轮换：`... members.cli rotate --name <member>`；旧 Token 立即 401。
- 撤销：`... members.cli revoke --name <member>`；不删除数据。
- 注意：`rotate` 会重新激活已撤销成员并发放新 Token。
- admin Token 只留在 Mac 的密码管理器，不装进手机。
- 管理员 Token 轮换后，清空 `.env` 中的 `API_ACCESS_TOKEN`，避免 `members.db` 丢失/回滚时用旧值重新创建 admin。
- 手机丢失：轮换该成员 Token → 在 Tailscale 控制台移除设备 → 用 admin 查看最近日志（仅内存 200 条）→ 在成员其余设备输入新 Token。

## 8. 验收命令

```bash
# 局域网（opt-out 时）
curl -s -o /dev/null -w '%{http_code}\n' http://<lan-ip>:8000/api/v1/health

# tailnet（不加 -k）
curl -s -o /dev/null -w '%{http_code}\n' https://<machine>.<tailnet>.ts.net/api/v1/health

# 无 Tailscale 的公网设备应解析失败或不可达
```

- 无/错误/已撤销 Token 必须 401。
- 非 admin 访问 `/api/v1/logs`、`/api/v1/agent/audit` 必须 403。
- 发起 `/api/v1/memory?query=<唯一标记>` 后，在 `/api/v1/logs`、`logs/` 与终端输出中检索不到该标记。
- 流式聊天应收到 `event: delta` 与 `event: done`；记录首字节延迟与长回答是否完整。
- `tailscale funnel status` 必须为 off。

## 9. 回退

```bash
tailscale serve reset
tailscale funnel status
tailscale down
```

若已迁移绑定：

1. `.env` 改回 `APP_HOST=0.0.0.0`，重启 FastAPI。
2. 确认局域网 `/health` 200、`/me` 鉴权正常。
3. iOS 地址改回 `http://<lan-ip>:8000`。
4. 无需改代码或迁移数据库。

## 10. 禁止事项

- 禁止 Funnel、公网隧道、路由器端口映射/DMZ/UPnP。
- 禁止 `FORWARDED_ALLOW_IPS=*` 或非回环值（应用会拒绝启动）。
- 禁止把 Tailscale 身份头当作认证依据。
- 禁止在 tailnet 内直连 8000（绑定迁移后应不可达；ACL 也不应放行）。
- 禁止使用家庭成员姓名等敏感信息作为机器名（ts.net 会进入 Certificate Transparency 日志）。
