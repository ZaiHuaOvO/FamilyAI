# 开发与协作规范

> 状态：**生效**

## 1. 工作方式

- 一次只实施一个可独立验收的阶段，不提前开发 RAG、长期记忆、提醒系统或客户端。
- 每个阶段开始前：阅读 README、相关阶段文档、前置验收记录与当前代码。
- 每个阶段结束前：运行测试与静态检查，记录真实结果，更新文档，提交 Git。
- 不伪造测试结果；说明运行了哪些命令、真实输出是什么。
- 发现文档与代码不一致时，先修正文档或代码，再继续。

## 2. Git 工作流

### 2.1 分支

- 默认分支：`main`。
- V1 由单人配合 AI 开发，采用“阶段提交”直接提交到 `main`，保持历史清晰。
- 如需较大改动，可使用短生命周期分支（如 `feat/chat-api`），合并后删除。

### 2.2 阶段提交

推荐一次阶段一次提交（或阶段内少量逻辑提交），不要把多个阶段混在一次提交中：

```text
chore: initialize family-ai repository
chore: install and verify local ollama model
test: verify ollama http api
feat: add FastAPI health endpoint
feat: connect chat endpoint to local ollama
feat: protect API with bearer token
feat: enable authenticated LAN access
test: cover authentication and chat validation
docs: add performance baseline
chore: release v1.0.0
```

提交信息使用 Conventional Commits 前缀：`feat`、`fix`、`test`、`docs`、`chore`、`refactor`、`perf`。实际内容必须与改动一致。

### 2.3 提交前检查

```bash
git status --short
git diff --cached
uv run pytest
uv run ruff check .
```

- 确认没有 `.env`、Token、聊天记录、家庭文件、日志或模型文件被暂存。
- `uv.lock` 与 `pyproject.toml` 一起提交。
- 文档更新与代码改动一起提交。

### 2.4 远端

```bash
git remote -v
git push -u origin main
```

- 远端：`https://github.com/ZaiHuaOvO/FamilyAI.git`
- 推送前确认工作区没有意外文件。
- 除非用户明确要求，不强制推送、不改写已推送历史。

### 2.5 发布

V1 全部验收通过后：

```bash
git tag v1.0.0
git push origin v1.0.0
```

## 3. 代码规范

- Python 3.12，使用类型注解。
- 路由层（`routers/`）只处理 HTTP 语义：认证、校验、错误映射。
- 模型通讯（`services/`）封装 Ollama 请求、超时与错误。
- 配置集中在 `config.py`，不散落读取环境变量。
- 不把业务逻辑与 HTTP 请求堆在一个文件里。
- 提交前 `ruff check` 必须通过。
- 注释解释“为什么”，不复述代码表面行为。

## 4. 测试规范

- 单元 / 接口测试默认 mock Ollama，不加载模型。
- 真实 Ollama 只用于少量集成测试或手工验收。
- 新功能必须覆盖：成功路径、认证失败、参数非法、上游失败/超时。
- 测试输出不得包含真实 Token。

## 5. 文档规范

- 文档库入口：[docs/README.md](../README.md)
- 进度记录：[docs/进度追踪.md](../进度追踪.md)
- 每个阶段完成后在 `docs/04-测试与验收/验收记录/` 新增记录。
- 被替代的文档移入 `docs/00-归档/`，不删除。
- 文档中的命令、路径、模块名必须与实际项目一致。
- 不在文档中写入真实 Token、`.env` 内容或家庭私人资料。

## 6. AI Agent 协作

项目规则见根目录 [`AGENTS.md`](../../AGENTS.md) 与 [`CLAUDE.md`](../../CLAUDE.md)。交付时要求包含：

1. 修改了哪些文件；
2. 运行了哪些命令与真实结果；
3. 已知限制；
4. 下一阶段建议。

## 7. 与外部顾问协作

每完成一个阶段，可提供：

- GitHub 仓库地址；
- 当前阶段与验收记录；
- 实际测试结果与报错信息；
- 希望审查还是允许修改。

> 不发送 `.env`、真实 Token、账号密码或家庭聊天记录。
