## 测试方法与结果

启动 FastAPI 后，使用 httpx（`trust_env=False`）按顺序执行请求。

| 测试 | 结果 |
|---|---|
| 预热 | 200，415ms |
| 连续 20 条 | 0 失败；min 223ms / avg 317ms / max 621ms（问题为“只回答数字”，回答很短） |
| 并发 2 条 | 均 200；墙钟 859ms；单条 415ms / 858ms |
| 并发 3 条（上限 2） | 200 / 200 / 429，并发保护生效 |
| 冷启动 | 4.3s，加载 2.2s |
| 热启动正常回答 | 1.7～3.0s |
| Ollama 不可达 | 503，78ms |
| Ollama 进程被停止 | 应用守护自动重启服务，随后聊天恢复 |
| 局域网调用 | Windows `192.168.5.18` 带 Token 聊天 200；无 Token 401 |
| 合盖/睡眠 | 合盖期间 API 失败；开盖唤醒后恢复 200 |
| 锁屏 / 显示器关闭 | 未单独测试（部署保持开盖 + 电源） |

## 资源占用

- 单请求：模型约 4.1GB，100% GPU，上下文 4096。
- 并发 2 请求后：模型约 7.1GB。
- 系统空闲内存约 24%，swap 已用约 6.0GB（并发测试后）。
- 模型空闲一段时间后会自动卸载，内存释放。

## 结论与建议

- 16GB 机器上并发 2 可用，但内存压力明显；若出现系统卡顿，将 `MAX_CONCURRENT_REQUESTS` 调为 `1`。
- 连续请求未导致服务崩溃。
- 短回答延迟约 0.2～0.6s；正常长度回答约 1.7～3.0s。
