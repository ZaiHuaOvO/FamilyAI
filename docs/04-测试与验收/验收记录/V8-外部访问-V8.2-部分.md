## 迁移后验证

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

结果：仅 `127.0.0.1:8000`。

| 路径 | 结果 |
|---|---|
| `http://127.0.0.1:8000/api/v1/health` | 200 |
| `http://192.168.5.18:8000/api/v1/health` | 连接失败（000） |
| `http://100.110.170.119:8000/api/v1/health` | 连接失败（000） |
| `https://mac.taild4f691.ts.net/api/v1/health` | 200，证书校验通过 |
| `https://mac.taild4f691.ts.net/api/v1/me`（无 Token） | 401 |
| `tailscale funnel status` | tailnet only，无 Funnel |

`/api/v1/logs`（admin）实测：

- Serve 转发的请求记录为 `client=100.110.170.119`（Tailscale IP），而不是 `127.0.0.1`；说明代理头被正确信任并改写。
- 本机回环请求记录为 `client=127.0.0.1`。
- 日志只有 path/status/client/member_id 等元数据，无查询串、Token 或正文。

说明：首次 HTTPS 连接时证书签发较慢，曾出现一次超时；证书签发完成后 TLS 1.3 与 HTTPS 请求均正常。Serve 的 Host 头仍未单独测量，`TrustedHostMiddleware` 继续不启用。

## ACL 验证

保存的 ACL 使用：

- `hosts.family-ai-mac = 100.110.170.119`
- `grants: src autogroup:member → dst family-ai-mac → ip 443`
- 未使用 tag，未执行 `tailscale up --advertise-tags`。

`tailscale debug netmap` 的 `PacketFilter` 实测：

- 规则数：1
- 目的：`100.110.170.119/32`，端口仅 **443**
- 来源：Mac 与 iPhone 两个 Tailscale IP（及对应 IPv6）
- 未包含 8000 或其他端口

说明 ACL 已生效，默认 allow-all 已被移除。

## Serve 上的聊天验证

使用 `.env` 中的 admin Token（不显示 Token）经 `https://mac.taild4f691.ts.net` 请求：

| 测试 | 结果 |
|---|---|
| 非流式 `POST /api/v1/chat` | 200；回复 2 字符；`duration_ms=3623` |
| 流式 `POST /api/v1/chat/stream` | 200；`content-type: text/event-stream`；1 个 delta（2 字符）；收到 `done`，`duration_ms=1084`；总耗时约 1.1s |

SSE 经 Serve 未被缓冲，`delta` 与 `done` 正常到达。
