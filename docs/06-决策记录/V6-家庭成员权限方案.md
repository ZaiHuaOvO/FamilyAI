# V6 家庭成员权限方案决策

> 状态：**待用户决定（2026-10-18）**  
> 前置：V5 已完成（`v5.0.0`）  
> 目的：在引入多成员前，明确身份、Token、数据归属与共享规则。

## 1. 当前状态

- 所有客户端共用一个 `API_ACCESS_TOKEN`。
- 记忆与任务数据结构预留了 `owner` 字段，但当前默认 `shared`。
- 知识库为全家共享、只读。
- 工具调用审计不区分成员。
- 请求日志只记录来源 IP。

## 2. 目标

- 夫妻/家庭成员拥有独立 Token，可分别使用。
- 记忆与任务支持**私有 + 共享**。
- 任何成员不能读取他人的私有数据。
- 管理员可以管理成员与审计，但不能通过普通接口偷看私有内容（除非明确设计）。
- 现有共享数据平滑迁移，不丢失。

## 3. 身份模型选项

| 方案 | 说明 | 优点 | 代价 | 建议 |
|---|---|---|---|---|
| **A. 多 Token 成员（推荐）** | `members` 表存成员名、Token 哈希、角色；每人一个 Bearer Token | 与现有认证兼容；无密码/会话系统；易撤销 | 需要 CLI 发放与轮换 Token | **推荐** |
| B. 用户名 + 密码登录 | 登录换取会话 Token | 更像传统账户 | 需要登录页、会话、防爆破、密码哈希 | 后续客户端阶段 |
| C. 单一共享 Token + 成员 Header | 客户端自称成员 | 改动最小 | 无法真正隔离，Header 可伪造 | 不推荐 |
| D. 暂缓 V6 | 保持全家共享 | 无改动 | 无法区分成员 | 视需求 |

## 4. 成员管理方式

| 方式 | 说明 | 优点 | 风险 |
|---|---|---|---|
| **A. CLI（推荐）** | 通过命令创建/列出/轮换/撤销成员 Token | 不增加网络攻击面；Token 只打印一次 | 需要登录 Mac 操作 |
| B. 管理员 API + 页面 | 通过 HTTP 管理成员 | 方便 | 管理员 Token 泄露影响大；需要额外页面与审计 |
| C. 手工改数据库 | 直接写 SQLite | 无代码 | 易出错，不推荐 |

## 5. 共享模型

| 数据 | 归属 | 可见性 |
|---|---|---|
| 记忆 | `owner` 成员 id | `private`（默认）/ `shared` |
| 任务 | `owner` 成员 id | `shared` 布尔字段（默认私有） |
| 知识库 | 全家 | 共享只读 |
| 工具审计 | 记录成员 id | 管理员可查看 |
| 请求日志 | 记录成员 id 与来源 IP | 管理员可查看 |

聊天 `use_memory: true` 时：

- 检索当前成员的私有记忆 + 全家共享记忆。
- 不检索其他成员的私有记忆。

任务列表：

- 默认返回当前成员的任务 + 共享任务。
- 管理员可以选择查看全部（单独参数，明确审计）。

## 6. 建议实现

### 6.1 数据模型

`data/members.db`：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `name` | 成员名（唯一） |
| `token_hash` | Token 的 SHA-256 哈希 |
| `role` | `admin` / `member` |
| `created_at` / `revoked_at` | 时间戳与撤销时间 |

- Token 使用高熵随机值，只在创建/轮换时打印一次。
- 认证时对 Bearer Token 做 SHA-256，再与库中哈希比较；使用常量时间比较。
- 撤销后立即失效。

### 6.2 CLI

```bash
# 创建成员并打印一次 Token
uv run python -m family_ai_api.members.cli create --name alice --role member

# 列出成员（不显示 Token）
uv run python -m family_ai_api.members.cli list

# 轮换 Token（旧 Token 立即失效）
uv run python -m family_ai_api.members.cli rotate --name alice

# 撤销成员
uv run python -m family_ai_api.members.cli revoke --name alice
```

### 6.3 接口变化

- 新增 `GET /api/v1/me`：返回当前成员的 id、name、role。
- 记忆与任务接口按成员过滤；共享项对全家可见。
- `POST /api/v1/memory` 增加可选 `shared: bool`（默认 false）。
- `POST /api/v1/tasks` 增加可选 `shared: bool`（默认 false）。
- 聊天 `use_memory` 只检索自己的私有记忆 + 共享记忆。
- Agent 写动作绑定成员；审计记录成员 id。
- 管理员接口暂不通过 HTTP 提供，使用 CLI。

### 6.4 迁移

- 现有 `API_ACCESS_TOKEN` 自动映射为 `admin` 成员（首次启动时写入哈希）。
- 现有记忆/任务/知识库保持 `shared`，不丢失。
- 迁移失败时不启动服务，避免半迁移状态。

### 6.5 安全

- Token 只以哈希形式存储；不写日志、不写 Git。
- 私有数据按 `owner` 过滤；不能通过列表/搜索/工具调用绕过。
- Agent 工具调用的动作绑定成员 Token。
- 审计与日志记录成员 id/name，不记录内容。
- 管理员不能通过普通查询读取成员私有数据；如需“管理查看”，必须单独设计并明确审计与确认。

## 7. 测试

- 成员创建/轮换/撤销；旧 Token 失效。
- 两个成员互相看不到私有记忆/任务；共享项可见。
- 聊天 `use_memory` 只使用自己的私有 + 共享记忆。
- Agent 动作绑定成员；跨成员确认失败。
- 迁移后现有共享数据仍可用。
- 日志/审计不含 Token 或内容。

## 8. 需要用户决定的事项

1. **身份模型**：多 Token 成员 / 用户名密码 / 单 Token + 标签 / 暂缓。
2. **成员管理**：CLI / 管理员 API + 页面。
3. **默认共享规则**：记忆默认私有、任务默认私有 / 全部共享 / 全部私有。
4. **现有 Token**：映射为 admin / 撤销并重新发放。

推荐：**多 Token 成员 + CLI 管理 + 记忆/任务默认私有且可共享 + 现有 Token 映射为 admin**。
