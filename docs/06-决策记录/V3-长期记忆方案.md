# V3 长期记忆方案决策

> 状态：**已决定（2026-10-18）**  
> 前置：V2 已完成（`v2.0.0`）  
> 目的：在实现长期记忆前，明确“记什么、怎么记、如何控制与删除”。

## 0. 最终决定

| 项目 | 决定 |
|---|---|
| 写入方式 | **显式记忆 + 自动提取混合** |
| 聊天默认行为 | **默认关闭**；客户端传 `use_memory: true` 才检索并注入记忆 |
| 记忆范围 | **全家共享**；数据结构预留 `owner` 字段，V6 再做成员隔离 |
| 管理界面 | **API + 记忆管理页面** |

自动提取的安全约束：

- 只读取本轮用户消息，不读取助手回答，不保存完整对话。
- 使用严格提示词：只提取用户明确说出的长期稳定事实/偏好/约定；不推断；不保存密码、证件、健康、财务等敏感信息。
- 单次最多 3 条，每条有长度上限。
- 来源标记为 `auto`，与显式记忆一样可查看、编辑、删除。
- 后台执行，失败只记录错误类型，不记录消息内容。
- 提供 `AUTO_MEMORY_ENABLED` 开关；默认开启，可随时关闭。

## 1. 目标

让 Family AI 在多次对话之间记住用户明确希望它记住的稳定信息，例如偏好、家庭约定、常用信息。

必须满足：

- 记忆可见、可编辑、可删除。
- 每条记忆记录来源与时间。
- 默认不永久保存全部聊天记录。
- 不进行隐藏画像或自动推断敏感信息。

## 2. 写入方式选项

| 方案 | 说明 | 优点 | 风险 | 建议 |
|---|---|---|---|---|
| **A. 仅显式记忆（推荐）** | 用户通过 API/页面主动添加记忆，例如“周末家庭活动优先户外” | 可控、可解释；不会悄悄保存聊天 | 需要用户动手 | **推荐** |
| B. 自动提取 | 每次对话后由模型总结并保存新事实 | 省事 | 可能保存错误、过期或敏感信息；审查成本高 | 暂不采用 |
| C. 混合：自动建议 + 用户确认 | 模型提出候选记忆，用户确认后写入 | 兼顾便利与可控 | 实现与交互更复杂 | 后续可评估 |
| D. 暂缓 | 保持 V2 | 无新增风险 | 无法跨对话记忆 | 视需求 |

## 3. 存储与检索

- 本地 SQLite：`data/memory.db`（已被 `.gitignore` 忽略）。
- 字段：`id`、`content`、`tags`、`source`、`created_at`、`updated_at`、`content_hash`、`embedding`，预留 `owner`（V6 家庭成员权限）。
- 去重：相同内容哈希不重复写入，更新 `updated_at`。
- 检索：使用现有 `qwen3-embedding:0.6b` 为记忆生成向量，按余弦相似度取 Top-K（默认 5），设置相似度下限。
- 上下文：记忆片段注入聊天时限制总字符（建议 2000），避免挤占模型上下文。
- 不使用记忆时完全不读取数据库。

## 4. 建议接口

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| `POST` | `/api/v1/memory` | 新增记忆 | 是 |
| `GET` | `/api/v1/memory` | 列表/搜索 | 是 |
| `PATCH` | `/api/v1/memory/{id}` | 修改内容/标签 | 是 |
| `DELETE` | `/api/v1/memory/{id}` | 删除单条 | 是 |
| `GET` | `/api/v1/memory/view` | 管理页面（页面数据仍需 Token） | 页面可访问 |

聊天集成：

- `POST /api/v1/chat` 与 `/api/v1/chat/stream` 增加可选 `use_memory`。
- 默认是否启用需要在决策中明确。
- 启用时，服务端检索相关记忆并作为上下文注入；不修改客户端传入的 `history`。
- 记忆内容不写入请求日志。

请求示例：

```json
{
  "content": "周末家庭活动优先安排户外。",
  "tags": ["家庭", "周末"]
}
```

## 5. 安全与隐私

- 所有记忆接口需要 Token。
- 记忆内容不进入日志、错误响应或 Git。
- 管理页面不在 HTML 中嵌入记忆数据；Token 只保存在页面内存。
- 删除为永久删除；需要时可以增加“清空全部”，但必须二次确认。
- 不自动读取聊天记录生成记忆。
- 默认不保存完整对话；聊天历史仍由客户端携带。
- 记忆可能包含个人信息，页面与 API 都应避免缓存（`Cache-Control: no-store`）。

## 6. 测试与验收

- CRUD、去重、检索排序、相似度阈值、上下文长度限制。
- 聊天注入：启用/禁用记忆两种路径。
- 认证：所有记忆接口无 Token 返回 401。
- 日志：记忆内容、聊天问题与回答均不出现。
- 页面：可加载、可新增/修改/删除，HTML 不嵌入数据。
- 真实测试：添加两条记忆，提问验证模型能使用；删除后不再使用。

## 8. 需要用户决定的事项

1. **写入方式**：A 仅显式 / B 自动提取 / C 混合建议 / D 暂缓。
2. **聊天默认行为**：默认启用记忆检索，还是客户端显式传 `use_memory: true` 才启用？
3. **记忆范围**：V3 先做全家共享记忆，还是从开始就按 Token/成员隔离？
4. **管理界面**：只提供 API，还是同时提供类似日志页面的记忆管理页？

推荐组合（已被用户调整为 1+2 混合）：**A + B + 显式 `use_memory` 开关（默认关闭）+ 全家共享 + 提供管理页**。自动提取按第 0 节的安全约束实现。
