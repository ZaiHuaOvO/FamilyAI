# V5 工具调用方案决策

> 状态：**待用户决定（2026-10-18）**  
> 前置：V4 已完成（`v4.0.0`）  
> 目的：在让模型调用工具前，明确工具范围、权限与确认流程。

## 1. 原则

- 最小权限：默认禁用；只开放明确列入白名单的工具。
- 写操作必须人工确认；读操作可以自动执行。
- 不提供任意 Shell、任意文件读写或智能家居控制。
- 工具参数必须按 JSON Schema 校验。
- 日志只记录工具名、状态与耗时，不记录参数内容或结果正文。
- 工具调用失败不能破坏现有聊天、知识库、记忆与任务功能。

## 2. 工具范围选项

| 类别 | 示例 | 风险 | 建议 |
|---|---|---|---|
| **A. 只读内部工具** | 今日简报、任务列表、知识库检索、记忆列表 | 低 | **首版推荐** |
| B. 内部写操作 | 新建/完成任务、新增记忆 | 中；需要确认 | 可纳入首版 |
| C. 外部只读 | 博客 API、GitHub Issues 读取 | 中；需要凭据与网络 | 后续评估 |
| D. 外部写/家居控制 | 发消息、改 GitHub、控制设备 | 高；不可逆或影响他人 | 暂不实现 |

## 3. 技术方案选项

| 方案 | 说明 | 优点 | 代价 |
|---|---|---|---|
| **A. 模型原生工具调用** | Ollama 支持的工具调用（tools 参数） | 与模型集成自然 | 依赖模型工具调用稳定性；需要适配 |
| B. 服务端规划 + 白名单执行 | 模型输出 JSON 动作，服务端校验并执行 | 可控、易审计、模型无关 | 需要更严格的解析与校验 |
| C. 外部 Agent 框架 | LangChain/LlamaIndex Agent | 生态成熟 | 依赖重、权限边界不清晰 |

推荐：**B（服务端规划 + 白名单执行）**。行为可预测，便于拒绝非法参数与记录审计。

## 4. 建议的首版（A + B）

### 4.1 只读工具

| 工具 | 作用 | 参数 |
|---|---|---|
| `get_briefing` | 今日/逾期任务与可选天气 | 无 |
| `list_tasks` | 按状态/到期筛选任务 | `status`, `due` |
| `search_knowledge` | 检索本地知识库 | `query`, `top_k` |
| `list_memories` | 检索长期记忆 | `query`, `limit` |

这些工具只读，自动执行，但整个请求仍需要 Token，并受聊天限流/并发保护。

### 4.2 写工具（需要确认）

| 工具 | 作用 |
|---|---|
| `create_task` | 新建任务 |
| `complete_task` | 标记任务完成 |
| `add_memory` | 新增记忆 |

确认流程：

1. 客户端请求模型执行动作。
2. 服务端返回 `pending_action`（id、工具名、参数摘要、过期时间），**不执行**。
3. 用户通过独立接口确认后执行一次；确认令牌单次有效、短时过期、绑定当前 Token。
4. 执行结果写入审计；拒绝或过期不执行。

### 4.3 接口草案

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| `POST` | `/api/v1/agent/chat` | 允许模型规划工具调用 | 是 |
| `GET` | `/api/v1/agent/tools` | 列出允许的工具 | 是 |
| `POST` | `/api/v1/agent/actions/{id}/confirm` | 确认并执行待办动作 | 是 |
| `POST` | `/api/v1/agent/actions/{id}/cancel` | 取消待办动作 | 是 |

### 4.4 审计

- 记录：时间、工具名、状态、耗时、来源（只读/写）、动作 id。
- 不记录：参数原文、结果正文、聊天内容、Token。
- 首版可保存在内存；后续可落 SQLite。

## 5. 安全边界

- 不开放 Shell、任意文件、网络任意请求或家居控制。
- 工具白名单由配置控制；默认关闭写工具。
- 写操作必须确认；不存在“模型自行确认”。
- 参数长度、枚举值、数量都要限制。
- 失败/超时返回明确错误，不自动重试写操作。
- 工具调用与普通聊天共享 Token、限流与并发保护。
- 外部服务凭据不得写入源码、日志或 Git。

## 6. 需要用户决定的事项

1. **工具范围**：只读内部 / 只读 + 内部写（确认）/ 再加外部只读 / 暂缓 V5。
2. **确认方式**：API 二次确认 / 管理页面确认 / 不需要确认（不推荐）。
3. **外部服务**：首版是否接入博客 API 或 GitHub（需要地址与只读凭据）。
4. **审计存储**：内存（简单）/ SQLite（可保留）。

推荐：**只读内部 + 内部写（二次确认）+ 不接外部服务 + 内存审计**。这样可以在不引入外部凭据的情况下先验证工具调用与权限流程。
