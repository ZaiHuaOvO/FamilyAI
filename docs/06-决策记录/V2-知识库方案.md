# V2 知识库 / RAG 方案决策

> 状态：**待用户决定（2026-10-18）**  
> 前置：V1.1 已完成（`v1.1.0`）  
> 目的：在开始写 V2 代码前，明确实现方式、数据边界与首版范围。

## 1. 目标

让 Family AI 能基于**用户明确指定的文档**回答问题，并给出可核对的来源。首版只服务家庭局域网，不做公网访问。

成功标准：

- 能索引非敏感的 Markdown / 文本资料（博客、开发文档）。
- 提问能检索到正确片段，并在回答中附带来源。
- 不自动扫描个人目录、聊天记录、照片或邮件。
- 不把文档正文、查询内容或 Token 写入日志或 Git。
- 本地运行，不引入需要公网账号的服务。

## 2. 实现方式选项

| 方案 | 组成 | 优点 | 代价 | 适用 |
|---|---|---|---|---|
| **A. 轻量自建（推荐）** | FastAPI + Ollama Embedding + SQLite + numpy 余弦检索 | 依赖少、完全可控、易审计；与现有认证/日志/测试一致 | 需要自己写分块、索引与检索代码；PDF 支持需另加 | 文档量中小（数千到数万片段） |
| B. LlamaIndex + Chroma | LlamaIndex 负责加载/分块/检索，Chroma 持久化 | 生态成熟，PDF/DOCX 加载器多；以后扩展方便 | 依赖明显变重；多一层抽象；调试成本更高 | 文档格式复杂、数量较大 |
| C. AnythingLLM | 独立的知识库产品 + 自带界面 | 上传、切分、检索界面成熟，开发量最小 | 多一个服务与端口；认证/网络边界要重新设计；资源占用更高 | 想先用现成产品验证需求 |
| D. 暂缓 V2 | 保持 V1.1 | 不增加复杂度 | 无法基于自有文档回答 | 当前需求不强 |

### 推荐：A（轻量自建）

理由：

- 现有 FastAPI 已经有认证、校验、限流、日志与测试，直接复用。
- 家庭文档量有限，SQLite + numpy 足够；避免为 V2 引入大型框架。
- 检索/索引接口保持独立，未来若文档量或格式增长，可平滑替换为 Chroma 或 LlamaIndex。
- 所有数据留在本机，边界清晰。

## 3. Embedding 模型选项

| 模型 | 大小 | 特点 | 建议 |
|---|---|---|---|
| **qwen3-embedding:0.6b** | 639MB | 中文/多语言，体积小，1024 维 | **推荐** |
| bge-m3 | 1.16GB | 多语言检索强，1024 维 | 中文效果优先时可选 |
| nomic-embed-text | 274MB | 体积最小，英文为主 | 仅英文资料时可选 |

内存评估：`qwen3.5:4b` 约 4.1GB + Embedding 0.6B 约 1GB，仍在 16GB 可承受范围；需在索引/查询时观察 swap。

## 4. 建议的首版范围

### 4.1 文档与索引

- 只支持 `.md` / `.txt` 首版；PDF/DOCX 后续评估。
- 用户通过命令显式指定目录或文件：

```bash
uv run python -m family_ai_api.knowledge.ingest ~/Documents/blog
```

- 自动跳过：隐藏文件、`.env`、`.git`、二进制文件、非文本扩展名。
- 分块：约 500 字符、重叠 80 字符，尽量按标题/段落切分。
- 每条片段保存：文档标题、相对路径、片段序号、内容哈希、更新时间、向量。
- 重复导入同一路径时先删除旧片段再写入；内容未变化则跳过。
- 数据文件：`data/knowledge.db`（本地、加入 `.gitignore`）。
- 示例资料放在 `knowledge.example/`，可提交；真实资料目录不提交。

### 4.2 检索与回答

- 查询流程：问题 → Embedding → 余弦相似度 Top-K（默认 4）→ 拼接上下文 → 本地模型回答。
- 上下文总字符上限（建议 6000），避免挤占模型上下文。
- 来源只返回标题、相对路径、片段序号与相似度；可选返回最多 200 字片段。
- 不返回绝对路径、文档全文或索引内部结构。

### 4.3 接口

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| `POST` | `/api/v1/rag/query` | 基于知识库回答问题 | 是 |
| `GET` | `/api/v1/kb/stats` | 文档/片段数量与最近索引时间 | 是 |

请求示例：

```json
{
  "message": "我在博客里写过哪些关于 FastAPI 的文章？",
  "top_k": 4
}
```

响应示例：

```json
{
  "answer": "根据你的博客，主要有……",
  "model": "qwen3.5:4b",
  "duration_ms": 1520,
  "sources": [
    {"title": "FastAPI 入门", "path": "blog/fastapi-intro.md", "chunk_index": 3, "score": 0.82}
  ]
}
```

### 4.4 安全与隐私

- 只索引用户显式指定的路径；不自动扫描主目录、聊天记录、照片或邮件。
- 不索引 `.env`、`.git`、隐藏文件与二进制文件。
- 查询接口必须带 Token；来源仅返回相对路径。
- 日志只记录时间、路由、状态码、耗时；不记录问题、检索片段或回答。
- 索引数据库与真实资料目录加入 `.gitignore`。
- 删除/重建索引必须由用户显式执行，不做自动删除。

## 5. 测试与验收

- 单元测试：分块、跳过规则、哈希去重、检索排序、API 认证与参数校验。
- 使用假 Embedding 测试检索逻辑，不依赖真实模型。
- 集成测试：索引 `knowledge.example/` 的示例文档，提问并核对来源。
- 验收：来源正确、无敏感内容进入 Git/日志、索引与查询延迟可接受。

## 6. 工作量估计

- 索引与存储：约 200～300 行 + 测试。
- 检索与 RAG 接口：约 150～250 行 + 测试。
- 文档与验收：半天。
- 总计约 1～2 个开发阶段；不需要数据库服务或容器。

## 7. 需要用户决定的事项

1. **实现方式**：A 轻量自建 / B LlamaIndex + Chroma / C AnythingLLM / D 暂缓。
2. **首批资料**：只使用非敏感博客与开发文档，还是也包含其他个人文档？
3. **是否需要 PDF**：首版只支持 Markdown/TXT，PDF 留到后续，还是首版就要？
4. **Embedding 模型**：默认建议 `qwen3-embedding:0.6b`；如果更看重中文检索质量，可选 `bge-m3`。

确认后，V2 将按“索引 → 检索 → 接口 → 测试 → 文档”的顺序实施。
