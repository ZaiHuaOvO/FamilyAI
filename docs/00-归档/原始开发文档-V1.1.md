# Family AI V1：Mac 本地大模型与 FastAPI 服务开发指南

> 版本：V1.1（后端方案调整版）  
> 编写日期：2026-10-18  
> 目标设备：MacBook Pro，Apple M3，统一内存 16GB  
> 开发方式：Claude + CC Switch + DeepSeek 辅助开发  
> 目标：让 Mac 运行本地模型，并提供带身份验证的 HTTP API，供家庭局域网设备调用。

---

## 0. 先看结论：为什么后端改用 FastAPI

**本版决定使用 Python + FastAPI，不继续使用 NestJS。**

这不是因为 NestJS 不好。对于普通业务 API，NestJS 完全够用，而且结构化程度高。如果这只是一个只转发请求的服务，NestJS 与 FastAPI 都能胜任。

但 Family AI 的长期目标不止转发聊天请求。后面可能会做文档解析、Embedding、RAG、知识库、模型工具调用和 AI 工作流。相关开源工具在 Python 生态中比较集中，例如 Ollama 的 Python SDK、LangChain 的 Ollama 集成，以及 LlamaIndex 的数据加载和 RAG 工具。FastAPI 又可以用少量代码建立具备输入校验和自动 API 文档的服务，因此更适合作为这个项目未来的 AI 应用后端。参考：[FastAPI](https://github.com/fastapi/fastapi)、[Ollama Python SDK](https://github.com/ollama/ollama-python)、[LangChain Ollama 集成](https://reference.langchain.com/python/langchain-ollama)、[LlamaIndex](https://developers.llamaindex.ai/python/framework/)。

| 选择 | 优点 | 对这个项目的判断 |
|---|---|---|
| **Python + FastAPI** | 与模型、文档处理、RAG、Embedding 等 AI 工具衔接自然；可自动生成 API 文档；起步简单 | **推荐** |
| NestJS + TypeScript | 你更熟悉；结构清晰，适合业务系统；与现有 NestJS 项目技术栈一致 | 如果未来主要是常规业务 API，也很合适；但会让 AI 相关能力分布在 TS/Python 两套服务中 |
| Go | 适合轻量、部署简单的网络服务 | V1 没有性能瓶颈需求；未来 AI 生态整合不如 Python 直接 |
| Rust | 性能和资源控制能力强 | 学习、调试和 AI 生态接入成本都偏高，不适合当前目标 |

你的主要开发工作会由 AI Agent 辅助完成，所以语言熟练度不是唯一决定因素。更重要的是：后端未来要接哪些能力、结构是否清晰、是否容易测试和持续维护。

**项目原则：**

- Ollama 负责加载模型和生成回答。
- FastAPI 负责统一 API、访问令牌、输入校验、限流、日志和错误处理。
- V1 不接数据库，不做长期记忆，不建立向量库，不自动导入聊天记录。
- 先只开放家庭局域网访问；以后确实需要外网访问时，再配置 Tailscale 等私有网络方案。
- Python 是本项目的后端语言，不代表你需要先系统学习 Python。让 AI Agent 按阶段实现；你重点检查架构、行为、安全、测试和验收结果。

## 1. V1 完成后应该是什么样

```text
iPhone / iPad / 家庭内的其他电脑
              │
              │ HTTP + API Token
              ▼
     FastAPI（本项目编写）
     - 身份验证
     - 请求校验
     - 超时与限流
     - 统一 API
     - 记录必要的运行日志
              │
              │ 只访问本机
              ▼
      Ollama：127.0.0.1:11434
              │
              ▼
      本地开源大模型
              │
              ▼
     MacBook Pro M3 / 16GB
```

### V1 要实现

- Mac 本机可以运行一个本地大模型并与之聊天。
- 可以通过 HTTP API 调用本地模型。
- FastAPI API 需要令牌才能使用聊天能力。
- 同一家庭局域网内的设备可以调用 FastAPI API。
- Ollama 的原始端口继续只监听本机，不直接暴露给局域网。
- 有基础测试、日志、错误处理和 README。

### V1 暂时不实现

- iOS/macOS 客户端。
- 长期记忆、RAG、向量数据库。
- 自动读取夫妻聊天记录、照片、邮件或整个电脑文件夹。
- 日历、天气、收衣服提醒或其他主动任务。
- 自动执行 shell 命令、控制家庭设备或修改文件。
- 公网直接开放 API。
- 微调或重新训练模型。

这些都属于后续阶段。V1 只解决一个问题：**让 Mac 稳定地运行本地模型，并通过一个受控 API 提供服务。**

## 2. 技术栈与开源项目

### 2.1 V1 直接使用

1. **[Ollama](https://github.com/ollama/ollama)**：本地运行和管理模型，提供 HTTP API。官方 API 文档：[API](https://docs.ollama.com/api/introduction)、[聊天接口](https://github.com/ollama/ollama/blob/main/docs/api.md)。
2. **[Python](https://www.python.org/)**：FastAPI 服务使用的语言。
3. **[FastAPI](https://github.com/fastapi/fastapi)**：定义 HTTP 路由、验证请求数据并生成 OpenAPI 文档。官方文档：[FastAPI Tutorial](https://fastapi.tiangolo.com/tutorial/)。
4. **[uv](https://github.com/astral-sh/uv)**：安装和管理 Python 版本、依赖与虚拟环境。它会维护项目依赖和 lock 文件，避免开发环境越来越难复现。文档：[uv 项目指南](https://docs.astral.sh/uv/concepts/projects/)。
5. **httpx**：FastAPI 通过它向本机 Ollama 发送 HTTP 请求。
6. **pydantic-settings**：从环境变量或 `.env` 读取服务配置，避免把 Token 写死在源码里。
7. **pytest**：测试 API 的行为，尽量用模拟请求测试，不要每次单元测试都加载大模型。

### 2.2 可选或后续使用

- **[Open WebUI](https://github.com/open-webui/open-webui)**：可选的聊天网页，连接 Ollama 便于测试模型；不是 V1 后端的必需组件。
- **[Ollama Python SDK](https://github.com/ollama/ollama-python)**：Ollama 官方 Python 客户端。如果采用它，也仍然可以用 FastAPI 作为自己的 API 层。V1 可先用 `httpx` 直接请求 Ollama HTTP API，减少抽象层。
- **[LangChain Ollama 集成](https://reference.langchain.com/python/langchain-ollama)**：后续需要模型编排、工具调用时评估；不要在 V1 为了“以后可能用到”而提前引入。
- **[LlamaIndex](https://developers.llamaindex.ai/python/framework/)**：后续建立文档知识库和 RAG 时评估。
- **[AnythingLLM](https://github.com/Mintplex-Labs/anything-llm)**：后续想先用成熟产品测试文档问答时评估。
- **[Dify](https://github.com/langgenius/dify)**：可视化工作流与 AI 应用平台，功能更多、部署也更复杂，不建议用于第一版最小服务。
- **[Tailscale](https://github.com/tailscale/tailscale)**：以后在外出时安全访问家里的 Mac。先不要做路由器端口映射。
- **[llama.cpp](https://github.com/ggml-org/llama.cpp)**、**[MLX-LM](https://github.com/ml-explore/mlx-lm)**：底层推理技术的替代或进阶方案。先跑通 Ollama，不要同时维护多个模型运行器。

## 3. 开发前准备

### 3.1 检查 Mac 与磁盘

在“苹果菜单 → 关于本机”确认设备信息。建议为模型、依赖和日志预留至少 20～30GB 可用磁盘空间；实际占用取决于模型和上下文设置。

### 3.2 安装基础工具

- 安装 [Xcode Command Line Tools](https://developer.apple.com/xcode/resources/)（如果尚未安装，可在 Terminal 执行 `xcode-select --install`）。
- 安装 [Git](https://git-scm.com/download/mac)。
- 安装 [VS Code](https://code.visualstudio.com/)；继续使用 Claude + CC Switch + DeepSeek 辅助开发即可。
- 安装 [Ollama for macOS](https://ollama.com/download)。
- 安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)。官方 macOS 安装方式之一：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

安装完成后，按安装程序提示重开 Terminal 或加载 shell 配置，并验证：

```bash
uv --version
git --version
```

如果 `git --version` 或 `uv --version` 找不到命令，先修复安装或 PATH，不要继续堆叠安装步骤。

### 3.3 创建独立 GitHub 仓库

建议仓库名：`family-ai`。不要放进 FlowersInk 网站仓库或公司仓库。

初始结构目标：

```text
family-ai/
├── README.md
├── AGENTS.md                 # AI 编程助手规则
├── docs/
│   └── V1-开发指南.md
├── src/
│   └── family_ai_api/
│       ├── __init__.py
│       ├── main.py
│       ├── config.py
│       ├── security.py
│       ├── routers/
│       └── services/
├── tests/
├── .env.example
├── .gitignore
├── pyproject.toml
└── uv.lock
```

这是目标结构，不要求你在创建仓库时全部手动建立。可以先用 `uv init` 创建标准 Python 项目，再让 AI Agent 按这个目标结构整理。

**安全要求：**真实 `.env`、API Token、私人聊天记录、家庭文档和密码不得提交到 GitHub。公开仓库和私有仓库都应该遵守这一点。

## 4. 阶段一：在 Mac 上运行本地模型

### 4.1 安装并确认 Ollama

打开 [Ollama 下载页面](https://ollama.com/download)，下载 macOS 版本并按提示安装。然后打开 Terminal：

```bash
ollama --version
```

如果命令正常返回版本，继续下一步。

### 4.2 下载入门模型

先从较小的量化模型开始，例如 Ollama 模型库中的 `qwen3.5:4b`。模型标签和文件大小可能变化，执行前以[官方模型页](https://ollama.com/library/qwen3.5)当前列出的名称为准。

```bash
ollama pull qwen3.5:4b
ollama run qwen3.5:4b
```

输入几条中文问题，确认能正常返回回答。之后可用 `ollama list` 查看本机模型，用 `ollama ps` 查看当前加载的模型。

M3 16GB 先以 4B 模型完成全部链路。只有在功能跑通、内存压力可接受之后，才尝试更大的模型。模型文件大小不等于运行时总内存，系统、上下文缓存和其他应用都需要内存。

### 4.3 阶段一验收

- [ ] `ollama --version` 正常。
- [ ] `ollama list` 能看到模型。
- [ ] `ollama run qwen3.5:4b` 能正常多轮对话。
- [ ] 记录回答质量、响应速度和活动监视器中的内存压力。
- [ ] 未安装额外的推理引擎，也未开放网络端口。

通过后，提交一次 Git 进度记录，再进入下一阶段。

## 5. 阶段二：直接测试 Ollama HTTP API

Ollama 默认本机 API 地址：

```text
http://127.0.0.1:11434
```

先查看已安装模型：

```bash
curl http://127.0.0.1:11434/api/tags
```

再测试聊天接口：

```bash
curl http://127.0.0.1:11434/api/chat \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3.5:4b",
    "messages": [
      {"role": "user", "content": "请用中文解释什么是本地大模型。"}
    ],
    "stream": false
  }'
```

如果模型回答出现在返回的 JSON 中，说明本地推理 API 已工作。如果提示模型不存在，请用 `ollama list` 核对准确标签。

### 阶段二验收

- [ ] `/api/tags` 返回模型列表。
- [ ] `/api/chat` 返回模型回答。
- [ ] 理解 Ollama API 与稍后自己编写的 Family AI API 是两个服务。
- [ ] Ollama 仍然只供 Mac 本机访问。

## 6. 阶段三：创建 FastAPI 项目

### 6.1 创建 Python 应用项目

在 GitHub 仓库根目录执行。若你已经有 `pyproject.toml`，不要重复初始化，先让 AI Agent 检查现有结构。

```bash
uv init --app --python 3.12 --name family-ai-api
```

这会以 `family-ai-api` 作为项目名称，标准 `src` 布局下的 Python 包名通常为 `family_ai_api`，与后文启动命令保持一致。如果当前目录并不是空项目，`uv init` 可能提示文件已存在；先查看现有文件再决定，不要删除已有内容。

安装依赖：

```bash
uv add "fastapi[standard]" httpx pydantic-settings
uv add --dev pytest pytest-asyncio ruff
```

`uv` 会维护 `pyproject.toml` 和 `uv.lock`。提交这两个文件，以便以后在另一台设备上恢复相同依赖版本。

### 6.2 让 AI Agent 建立项目结构

把目标目录结构和本指南交给 Claude Code，让它先只分析仓库当前状态并提出实施计划。确认后，再分阶段生成代码。不要一次性生成完整的 AI 平台。

至少需要以下职责清晰的模块：

- `main.py`：创建 FastAPI 应用、挂载路由、处理应用生命周期。
- `config.py`：加载环境变量与服务配置。
- `security.py`：验证 API Token。
- `routers/health.py`：健康检查接口。
- `routers/chat.py`：聊天接口。
- `services/ollama_client.py`：与本机 Ollama 通讯。
- `tests/`：接口、参数和认证测试。

模块名称可以根据 AI 生成的项目规范调整，但不要把所有业务和 HTTP 请求塞在一个巨大文件里。

### 6.3 启动最小服务

先让 Agent 只实现一个健康检查接口，然后启动开发服务。具体启动命令需要符合实际 `pyproject.toml` 和包结构；如果采用标准 `src` 布局，通常可以使用类似命令：

```bash
uv run uvicorn family_ai_api.main:app --reload --host 127.0.0.1 --port 8000
```

注意：若项目生成的 Python 包名不是 `family_ai_api`，应使用真实包路径，不要机械复制命令。`--reload` 只用于本机开发，不应用作最终长期运行配置。

浏览器打开：

```text
http://127.0.0.1:8000/docs
```

FastAPI 通常会根据路由自动生成交互式 OpenAPI 文档。如果看到文档页并且健康检查返回正常状态，说明最小 API 服务已经工作。

### 阶段三验收

- [ ] 项目能通过 `uv` 安装依赖。
- [ ] `uv.lock` 已生成并提交。
- [ ] FastAPI 服务可启动。
- [ ] 健康检查接口可访问。
- [ ] `/docs` 能显示接口定义。
- [ ] Ollama 调用代码尚未与路由混在一起。

## 7. 阶段四：实现自己的聊天 API

### 7.1 配置本机 Ollama

在 `.env` 中配置真实运行值（该文件不得提交 Git）：

```dotenv
APP_HOST=127.0.0.1
APP_PORT=8000
OLLAMA_BASE_URL=http://127.0.0.1:11434
AI_MODEL=qwen3.5:4b
API_ACCESS_TOKEN=请替换为真正的随机长密钥
REQUEST_TIMEOUT_SECONDS=180
MAX_MESSAGE_CHARS=6000
```

把变量名称同步写进 `.env.example`，但只放占位值。服务必须从配置读取模型名、地址和密钥，不能把真正的 Token 写在源码里。

生成一条随机密钥的示例命令：

```bash
openssl rand -hex 32
```

复制结果到本地 `.env`，不要把真实结果发给 AI、放进 README、日志或 GitHub Issue。

### 7.2 V1 接口设计

先实现下列接口，避免为了未来功能做过度设计：

| 方法 | 路径 | 用途 | 认证 |
|---|---|---|---|
| `GET` | `/api/v1/health` | 仅返回 API 是否运行，不泄露配置细节 | 可不认证，但返回内容必须最小化 |
| `GET` | `/api/v1/models` | 返回本服务允许使用的模型 | 需要 Token |
| `POST` | `/api/v1/chat` | 请求本机 Ollama 并返回模型回答 | 需要 Token |

请求示例：

```json
{
  "message": "请解释一下 RAG 是什么。"
}
```

响应结构示例：

```json
{
  "message": "RAG 是先检索相关资料，再把资料交给模型生成回答的一种方法。",
  "model": "qwen3.5:4b",
  "duration_ms": 1234
}
```

上面响应中的内容和耗时只是示例。真实服务应该返回真实模型结果和实际测得的耗时。

第一版先做非流式请求，便于定位问题；等调用稳定后再添加逐字输出/流式响应。V1 不保存历史聊天，也不应宣称模型会自动记住过去的对话。

### 7.3 服务内部流程

```text
客户端请求
    ↓
FastAPI 检查 Token
    ↓
校验 message 长度和请求格式
    ↓
应用并发限制与超时
    ↓
httpx 请求 http://127.0.0.1:11434/api/chat
    ↓
解析 Ollama 响应
    ↓
返回统一的 JSON
```

让 Agent 使用异步 HTTP 请求、合理超时，并正确处理连接错误、Ollama 尚未启动、模型不存在、模型生成超时等情况。对外返回安全且可读的错误信息；不要把完整异常堆栈、系统路径、环境变量或密钥返回给客户端。

### 7.4 API Token 与输入保护

- 使用 `Authorization: Bearer <token>` 或同等安全的 Header 传递 Token。
- 使用 FastAPI 的依赖机制集中验证访问令牌；比较密钥时使用安全的常量时间比较方式。
- 缺少或错误的 Token 必须返回 `401` 或 `403`，不可继续调用模型。
- `message` 必须是非空字符串，并设置最大字符数。
- 限制请求体大小和并发聊天数，避免多个请求同时占满 16GB 内存。
- 只允许服务端配置的模型，不要让调用者随便指定任意模型名或任意 Ollama 地址。
- 对 Ollama 请求设置超时；失败时返回明确的 `4xx/5xx` 错误。
- 日志只记录时间、路由、响应码、耗时和必要的错误摘要。不要记录 Token，不默认写入聊天正文。
- 不允许 V1 API 任意执行 shell 命令、读取任意文件或控制家居设备。

可以在 Agent 设计审查通过后再加入速率限制库，但不能省略认证、输入大小限制、超时与并发保护。

### 7.5 本机测试

健康检查：

```bash
curl http://127.0.0.1:8000/api/v1/health
```

无 Token 请求聊天，应当被拒绝：

```bash
curl -i http://127.0.0.1:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"你好"}'
```

带 Token 请求聊天：

```bash
curl http://127.0.0.1:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_REAL_TOKEN' \
  -d '{"message":"请用中文介绍一下你能做什么。"}'
```

把 `YOUR_REAL_TOKEN` 替换为 `.env` 中的真实值。不要把这条带真 Token 的命令提交到仓库或截图公开。

执行测试：

```bash
uv run pytest
uv run ruff check .
```

如果 AI Agent 生成的测试需要实际调用模型，要求它优先把 HTTP 层与模型服务解耦，并用 mock/模拟响应覆盖大部分测试；只有少量集成测试才调用真实 Ollama。

### 阶段四验收

- [ ] `/api/v1/chat` 返回本地模型的实际回答。
- [ ] Token 缺失或错误时请求被拒绝。
- [ ] 空消息、超长消息或非法 JSON 被拒绝。
- [ ] Ollama 关闭时，API 能有限时间内返回错误，而不是无限等待。
- [ ] 日志与错误响应不泄露 Token、配置和聊天全文。
- [ ] 测试和静态检查通过。

## 8. 阶段五：在家庭局域网开放 API

这一步必须在阶段四的认证和输入校验已验证通过后再执行。

### 8.1 只改变 FastAPI 的监听地址

本机开发时使用：

```text
127.0.0.1:8000
```

准备从家庭 Wi-Fi 设备访问时，才把 FastAPI 的监听地址切换为 `0.0.0.0` 或等效的网络监听配置。配置项可使用 `.env` 管理。

**不要修改 Ollama 的监听地址。** Ollama 继续只监听 `127.0.0.1:11434`，让 FastAPI 成为唯一对局域网提供访问的服务。

### 8.2 查询 Mac 的局域网 IP

在 macOS 的 Wi-Fi 详细信息里查看 IP 地址，假设示例为：

```text
192.168.1.20
```

请使用 Mac 实际的局域网地址。IP 可能会变化，稳定使用后可以在路由器里为 Mac 设置 DHCP 地址保留；V1 不需要做端口映射。

### 8.3 从另一台设备测试

在同一家庭 Wi-Fi 下的电脑运行：

```bash
curl http://192.168.1.20:8000/api/v1/health
```

再带 Token 调用聊天 API：

```bash
curl http://192.168.1.20:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_REAL_TOKEN' \
  -d '{"message":"请确认家庭局域网 API 可以正常调用。"}'
```

如果连接失败，依次检查：

1. Mac 和测试设备是否连接同一个局域网。
2. FastAPI 是否已经绑定网络接口，以及服务是否正常运行。
3. IP 和端口是否正确。
4. macOS 防火墙是否拦截 Python 服务的入站连接。
5. Token 是否有效。

不要为了排错直接关闭防火墙，也不要顺手打开路由器端口转发。

### 8.4 网络与客户端限制

- 不开放 11434 端口。
- 不把 8000 端口映射到公网。
- 不通过 URL 查询参数传递 Token。
- 原生 iOS 请求不受浏览器 CORS 约束；如果以后有网页前端，再将 CORS 来源精确配置为受信任地址，不使用任意来源。
- 需要外出时访问家中服务，后续先评估 Tailscale 等私有网络，不直接开放公网。
- 家庭 Wi-Fi 的任何设备都不应因“连接了 Wi-Fi”就自动被视为可信；认证仍必须开启。

### 阶段五验收

- [ ] 家庭局域网中的另一台设备能调用 FastAPI。
- [ ] 未带 Token 的聊天调用仍然失败。
- [ ] Ollama 端口仍只监听本机。
- [ ] 未进行公网端口映射。
- [ ] macOS 防火墙保持开启，仅允许必要访问。

## 9. 阶段六：稳定性与服务器运行习惯

### 9.1 MacBook 作为服务器的限制

M3 + 16GB 足以开始运行较小的本地模型并服务于家庭低并发请求，但 MacBook 仍是笔记本：睡眠、合盖、网络断开、系统更新或重启都可能中断服务。

- 长时间测试时连接电源。
- 在 macOS 系统设置中检查电源与睡眠行为，不要假定合盖后服务仍会工作。
- 先验证锁屏、显示器关闭后 API 是否还可用，再决定如何长期运行。
- 不要在第一天就同时折腾 launchd、Docker、反向代理、自动更新和公网访问。
- 先使用手动启动方式开发；服务稳定后再配置开机/登录后启动和健康检查。

### 9.2 性能记录

用固定的 5 条问题做基线测试，记录：

- 第一次加载模型需要多久。
- 模型已加载后，简单回答需要多久。
- 长回答的延迟与生成速度。
- 连续 20 条请求是否稳定。
- 两条请求同时到达时是否影响响应或造成明显内存压力。
- 活动监视器中的内存压力是否持续偏高。

V1 面向自己与家人少量使用，不以高并发、多人同时推理或云服务级可用性为目标。如果模型使整个 Mac 明显卡顿，先降低模型体量、上下文或并发，而不是加复杂基础设施。

### 阶段六验收

- [ ] 连续 20 条常规请求未使服务崩溃。
- [ ] 模型停止或服务中断后，能找到原因并恢复。
- [ ] 记录性能基线及已知限制。
- [ ] 确认锁屏、显示器关闭、睡眠分别对服务有什么影响。

# Family AI 项目规则

## 12. 下一阶段路线图

V1 完成后再决定每一项是否需要实现：

- **V1.1：调用体验**——流式输出、对话历史传递、请求日志页面。

## V1 最终完成定义

以下项目全部满足，才算 V1 完成：

- Mac 能稳定运行一个本地模型。
- `curl` 可以直接调用 Ollama 本机 API。

达到以上条件后，Mac 才具备作为 Family AI 后端 V1 的基础。不要因为模型能聊天，就提前开始导入全家聊天记录或添加能够操作外部服务的 Agent。
